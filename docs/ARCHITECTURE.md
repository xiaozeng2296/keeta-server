# 服务边界与优化顺序

建议先维持一个代码仓库、多个独立运行进程。当前共享签名器、队列和面板的模块划分可以继续用；应先拆开进程与状态所有权，再考虑独立服务或多个仓库。

## 当前结构

- Web为Flask面板，默认可以在同进程启动ExecutionManager线程；`--no-worker`关闭内嵌执行器；新仓库另提供 `farm.executor` 独立进程入口，内部仍复用相同 ExecutionManager。
- MySQL保存控制信息、账号材料、数据库任务及用量；本地队列用SQLite与文件保存批次、attempts和响应，通过local_ledger向面板汇总。本地业务响应不上传MySQL，但账号来源与管理仍与控制数据库有联系。
- `farm/fullsign.py`是共享签名器；采集Worker直接调用。`keeta_rpc.py`提供同套算法的HTTP入口，持有进程内签名缓存/锁，不是完全无状态服务。
- 代理路由在Worker内按账号选择；Clash核心或桥接代理属于独立进程。a7维护必须沿用该账号的出口及状态锁。
- 本地与MySQL执行链仍有重复调度/策略逻辑；不可售详情豁免目前只在本地链启用。推荐发现、批次准备、监视/验收已参数化为 `farm.recommendations` 和 `farm.batch_*`，迁移时保留原调度语义。

## 建议部署边界

| 单元 | 职责 | 不应承担 |
|---|---|---|
| Web/API进程 | 导入、配置、创建/停止任务、读取汇总、下载交付 | 在HTTP请求线程内跑长采集、整批Excel导出或全量扫描账本 |
| Collector Worker进程 | 独占账号状态、额度预留、a7维护、签名发送、扩展任务、断点恢复 | 依赖Web页面常驻或由刷新页面触发采集 |
| 共享协议库 | 规范化输入、a2/a5/a9、provider、字段状态变换 | 自行选择账号、清冷却、发业务网络请求 |
| 可选签名RPC进程 | 为外部调用方提供相同算法的接口 | 与Worker同时无协调地推进同一账号计数 |
| Proxy进程/适配层 | 明确出口、连接、节点并发及链式路由 | 把所有403判断成网络故障或无界轮换出口 |
| Export任务 | 从已落盘结果生成Excel/ZIP和完整度报告 | 占用业务发包线程或每几秒重写整个结果集 |

a7维护暂不拆成独立微服务：它与同账号的签名序号、b16事件、出口和持久化边界耦合。由持有账号租约的Worker完成，能避免新a7与旧计数交叉写入。以后如签名RPC承接生产请求，需要先定义单一状态所有者及版本校验；另一种选择是调用方提供不可变快照和已预留序号，让RPC只计算。

## 优先顺序

1. **发布可复现**：正式源码不放`.private`，统一清单、依赖和干净目录测试；每个版本能回滚代码，但不能回滚签名计数、额度和已发送attempts。本轮完成源码独立、通用批次入口和文档整理。
2. **Web与Worker分进程**：让Worker领取持久队列，持有带租约的账号/安装锁；优雅停止先停止领取再落账。Web重启不影响采集；Worker退出后显示真实状态，不能无限重启绕过403保护。
3. **抽取共同任务策略**：主菜单/render规划、闭店/不可售规则、业务响应判断与完整度统一；MySQL和SQLite作为不同存储适配器。先消除语义分叉，再大规模改目录名。
4. **减少面板与导出开销**：请求日志分页、进度增量汇总、按批次/账号/时间索引；原始大响应留文件或对象存储。导出按结果版本触发，放到独立任务；不要每次点页面扫描全部账号历史SQLite。
5. **协议更新可定位**：同一次请求绑定明确SDK/provider/profile及代码版本；未知配置失败时给出具体输入缺口。用合成向量、原生对照、完整发送字节校验和有界真实验证逐层推进。
6. **容量与故障验证**：跨业务日、额度耗尽、出口短暂失败、Worker退出、重复任务、磁盘满和多小时运行分别测；报告实际成功吞吐、维护请求、等待时间和未完成原因。

## 仓库与资料

运行与协议学习可暂留同一仓库：`farm/`管理与执行，`mtgsig/`协议库，`rpc/`接口部署，`tests/`回归，`docs/`当前指南、`docs/research/`证据、`docs/archive/`历史。本仓库已经按运行依赖整理，不继承抓包与大型dump历史。

原始二进制、抓包、账号、数据库、密钥、代理授权和采集结果不属于源码提交。它们单独存储，运行迁移时仍必须保留用量、冷却及状态版本；不能为了“干净启动”把额度和序号重置。
