# 服务与存储边界

当前只保留一条调度链：Web → MySQL 任务队列 → 独立 Worker。已移除 SQLite、本地账号快照的运行时接管逻辑、第二套批次执行器和监督进程。

| 单元 | 当前职责 |
|---|---|
| Web (`farm.web.app`) | 导入账号/店铺、配置路由、排队/停止、读取汇总和下载；页面关闭不影响 Worker |
| Worker (`farm.executor`) | 账号/安装锁、额度预留、a7 维护、签名、网络请求、任务扩展、结果提交及导出 |
| MySQL | 账号加密材料、用量、冷却、任务/attempts 元数据、响应文件的哈希引用 |
| 本机 `.private/responses/` | 原始业务 JSON 和失败诊断；新响应体不上传 MySQL |
| 本机 `.private/request-journal/` | 响应先加密落盘，SQL 提交失败后仅重放提交，不重发 HTTP |
| 本机 `.private/account-checks/fingerprint-maintenance/` | 小型 a7 维护计数 JSON；文件锁、原子写、重启保留滑动 24 小时限额 |
| 签名库及可选 RPC | Worker 直接调用共享签名库；8799 RPC 为离线计算/对拍入口，不与 Worker 共同推进生产账号状态 |
| 独立代理核心 | 每账号明确出口；同路由限流，a7 与业务使用相同出口；不修改桌面 Clash 全局选择 |

`task_results.response_blob` 为兼容旧表结构保留名称，新内容仅为 `KLF1:` 加 SHA256。失败诊断在 SQL 中也只保存加密文件引用。读取兼容历史压缩记录，复制旧结果时先转成本机引用；文件缺失或哈希错误会明确失败，不能视为完成。

额度在发包前预留、发送前转为已用；进程中断的未知请求保守计入用量。账号和安装锁跨进程生效。普通接口无额外等待，同账号定制详情保留配置间隔。不同账号按可用额度/接口能力轮换，每条路由有共享并发上限。连续四次 403 且涉及至少两个账号终止本轮；重启不会抹掉该证据。

闭店和不可售详情规则现在统一在 MySQL Worker 与导出验收中。商品必须已记录且具备明确不可售证据才跳过。任务成功、HTTP200、完整交付分别统计。

默认交付 ZIP 只有 `delivery.xlsx`。超长字段按 Excel UTF-16 长度限制分片到“长字段内容”工作表，含原表引用与校验哈希；完整度报告、运行日志及响应文件保留本机供排错，不混入交付包。

备份需要同时覆盖 MySQL、小型状态 JSON、加密密钥和本机响应/交付目录。只有 MySQL 备份不能恢复已经外置的响应体。Web 与 Worker 应共享同一数据目录；多台 Worker 尚未提供远程文件存储协调，不应直接共享数据库而各自使用不同响应目录。
