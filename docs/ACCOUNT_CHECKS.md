# 账号检查与本地大批次运行

所有脚本通过 `scripts/python.sh` 选择环境变量、venv 或本机解释器路径，可从任意目录执行。输出只包含账号 ID、接口、状态和汇总，不打印 token、完整签名或代理密码。检查报告保存到 `exports/account-check-时间-随机码/report.json`。

## 日常检查

在项目目录执行：

```bash
# 完全离线：检查每个账号四种请求的完整 a2 与实际发送字节是否匹配。
./scripts/check_account_signatures.sh --all

# 检查代理连通和实际出口 IP；不访问采集业务接口。
./scripts/check_proxy.sh --route clash --execute
./scripts/check_proxy.sh --route saved-default --execute

# 先预览；指定一个已有任务中的营业店 ID。
./scripts/check_account_apis.sh --accounts 97,98 --shop-id 159463099

# 真正请求；每个账号最多四次业务请求，顺序执行，不自动重试。
./scripts/check_account_apis.sh --accounts 97,98 --shop-id 159463099 --execute
```

示例店铺不保证当前营业，替换为面板中要验证的店铺 ID。流程为店铺信息 → 主菜单 → 根据本次菜单中的分类/菜品 ID 发一条 render → 营业状态确认后取一条有定制选项的菜品详情。闭店跳过定制详情；菜单没有可用目标则记录未测试，不编造 ID。若店铺信息失败，其后接口记录未验证。render 返回 200 仍会检查本次请求的菜品是否齐全。

`--accounts` 支持 `97,98,100-105`；`--all` 明确选择所有现有账号。未指定 `--execute` 的接口检查不会发业务请求。签名检查永远不发业务请求，也不持久化试算的签名计数。代理连通成功或离线签名通过，都不代表业务服务器一定接受请求。

报告中的 `passed`、`failed`、`not_tested` 分开统计。冷却、额度不足、账号忙、闭店跳过都不会自动标记成废号或删除账号。多账号连续 403 时，检查提前停止并保留已得到的结果。

## 状态与计数的来源

账号按活动会话在所有本地批次中定位最新快照，不只读取 latest 批次。先核对数据库活动会话：同一会话且远端仍暂停时使用最新本地加密快照；若已经重新导入新的活动会话，则使用新会话；若同一会话的远端被解除暂停，返回 `account_state_requires_reconciliation`，避免两份计数相互覆盖。本地检查任务单独保存到 `.private/account-checks/`；每次请求前同步保留签名计数和扣除本地额度，请求后保存结果与冷却。原批次的店铺任务与结果不混入检查任务。检查失败的响应体仅存在加密私有记录中，公开报告只给 HTTP 状态、结果分类和响应哈希。

命令行普通检查遵守已有冷却。面板手动恢复探测可以跨冷却，每个接口最多一次请求，仍受硬额度、账号互斥与在途请求对账限制。成功自动解除实际验证接口冷却，保留其他接口冷却及已用额度；手动解除按钮将该接口标成待验证，不启动采集。

其他账号通过现有数据库 Worker 的账号锁、设备锁、预算及结果记录执行单次检查。明确指定的手动检查允许测试已暂停的账号，但不解除账号暂停，普通命令行检查不清除冷却或额度。此权限只允许绑定一个账号和一个检查任务，不用于批量采集。

本地执行器和检查脚本共用文件锁；采集运行时检查返回 `local_batch_is_running`，防止同账号同时使用两份计数。检查异常中断时保留 `probe_inflight` 标记并阻止继续采集，避免把未知发送当成未发送。需要根据对应私有检查目录中的 attempts 结算后再恢复，不能直接删标记绕过。

## 自动调度

本地执行器按账号池顺序轮换，跳过忙碌、接口冷却、账号休息或额度不足的账号。同一账号不并发；普通接口没有额外间隔，只有两次定制详情之间保持配置的间隔。

- 有其他可用账号：继续领取任务。
- 所有账号暂时冷却/任务退避：保留进程，显示原因及预计重试时间，到时自动继续。
- 当日额度用完：等待巴西业务日切换，归档旧用量并建立新一天的额度；独立的 24 小时休息不会被午夜清除。
- 网络异常：共享出口按 60、120、240 秒等逐步退避，最多 900 秒；保留每条任务的重试上限。中断后再次启动会读取原退避时间。
- 全批连续四次 HTTP 403 且涉及至少两个账号：仍保留整轮暂停，防止把共同故障扩散到整个账号池。403 不自动认定为永久封号或网络故障。
- 手动 STOP、明确本地错误、重试已耗尽或没有所需材料：如实保留阻塞，不能宣称已经完成。

执行器不会每 15 秒重写大批次 Excel：状态每 15 秒刷新，工作簿默认最多每 120 秒且结果变化时刷新，结束时最终导出。SQL 候选按接口收敛，账号轮换不需要反复遍历所有店铺任务。

正式运行入口：`python -m farm.local_batch 本地批次目录`，须先准备批次manifest与账号快照。推荐使用 `scripts/start_batch.sh` 的独立监督入口。STOP 文件存在时不会自动恢复，也不会重新创建批次或重跑已成功的任务；检查命令本身不解除批次暂停。

## Clash 配合动态代理

链路为 `采集程序 → 本机 Clash → IPFoxy → 目标接口`，目标看见的是 IPFoxy 的最终出口，不是两种出口同时各增加一个并发。并发数与出口数独立。

须先在本机私有配置中保存带 Clash 前置的 IPFoxy 默认配置。以下命令只保存路由，不启动采集、不清除暂停或冷却：

```bash
# 先预览默认代理配置（不会输出密码）。
./scripts/set_local_proxy.sh --route saved-default
# 将默认 IPFoxy 链式配置加密保存给当前本地批次。
./scripts/set_local_proxy.sh --route saved-default --execute
# 切回仅 Clash。
./scripts/set_local_proxy.sh --route clash --execute
```

`--local-batch` 可指定其他本地批次目录，默认使用 latest 指向的批次。路由凭据只写入该批次 `.private/.../route.enc`，不写入公开 manifest 或 ZIP。当前批次运行时配置修改会因文件锁被拒绝。

配置开启 IPFoxy 动态刷新后，403 或网络异常会安排一次出口刷新：先等待所有在途请求结束，同一路由至少间隔 5 分钟调用一次刷新链接，记录实际出口是否变化。刷新成功不清除账号冷却，不把网关接受刷新当成出口已变化。跨账号连续 403 的暂停规则仍然适用。
