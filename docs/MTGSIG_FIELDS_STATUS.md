# mtgsig `a0`–`a10`、`x0` 当前恢复状态

本页维护当前实现与证据边界。阶段更新保留在 [字段研究历史](research/FIELD_STATUS_HISTORY_20261004.md)；当前行为看下表，运行规则看 [采集流程](COLLECTION_FLOW.md)。

## 先给结论

历史字段表 `docs/archive/root/V5_SIGN_FIELDS.md` 确实列出了 `a0`–`a10` 全字段；实际离线签名器是 `farm/fullsign.py`。目前**已有全字段组装与支持配置下的离线签名、a5/a9 加解密**，2026-09-29 也补上了采集缓存的周期续接。仍需已有的设备观察、SDK 配置与会话输入；这与“完整重建原生采集器、初始化状态及服务端身份分配”是不同范围。

本页按当前代码和离线验证修正历史字段表。`docs/archive/root/V5_SIGN_FIELDS.md` 中“a1 每设备唯一”“a10 每签递增”“服务端只校验 a2 前半”等旧表述不能继续作为当前结论。下述能力也不等于任意版本或任意服务端请求都已验证成功。

## 字段矩阵

| 字段 | 当前实现 | 恢复程度 | 主要边界 |
|---|---|---|---|
| `a0` | 从身份档写入 | 已知 | 协议版本/配置值；没有独立的“推导算法” |
| `a1` | 从身份档写入，参与密钥派生 | 当前原生应用配置来源已证 | 本次 getter 取主 App Info.plist 的 ak，与签名逐字一致；另有 akd/内置默认分支，不能推断跨版本始终同值，更不是每设备唯一。解码须保留同条签名原始字节 |
| `a2` | `farm/fullsign.py:compute_a2()` | 566 条原生布局完整对拍通过 | HMAC、canonical URL、Body UTF-8 前 16,200 字节、完整 payload 和 pass1/pass2 已验证；需要准确请求字节、`a1`、两类计数和 signing profile。4 条 x0=4 不在当前支持布局内；签名上限不截断实际 HTTP Body |
| `a3` | 原样导入并用于 a5 seed/a2 payload | 原生 provider 配置成员来源已证 | 对象 +0x58 默认 20，本次配置处理成功改为 25；同 App/build 可以出现两者。动态配置 AES-CBC 解出 a3/salt，真实盐与原生对象逐字匹配；mask shift=(a3+11)%36，但不能只用 a3 猜 salt/profile |
| `a4` | `FullSigner.sign()` 取当前 Unix 秒 | 已恢复 | 时间戳可现算，但原生与服务端允许的时钟/偏移仍是运行条件 |

| `a6` | 从身份档写入并参与 a2 payload | 已定位为 SDK 原子状态位集合 | 本次 566 条原生布局和真机会话均为 0；已证开发团队与 PIC 绑定校验失败写 S=8，下游累计 0x01/0x02；其他位含 PIC/XBT 完整性、兼容标签和 nil 查询分支，完整枚举仍有边界 |
| `a7` | `bootstrap_identity` 可生成本地候选；成功响应可回填服务端 XID | 分两阶段；注册链与显式启用的店铺链已接入 | 服务端 XID 来自 `/fingerprint/v1/info/report` 的 data.result；保存 interval 分钟有效期、serverTimestamp 和真实 b16 事件；36个上报接受、33个营业店四接口通过，#44多次到期续接成功；#71/#121/#126店铺仍403，原生m315首次校时未接入维护器 |
| `a8` | `bootstrap_identity` 可生成本地候选；成功响应可回填服务端 DFP | 分两阶段 | 本地 dfpID 可复现；真正服务端 DFP 来自 `/v5/sign`/相关响应，不能离线生成任意新值 |
| `a9` | `mtgsig/a9_codec.py` 编解码；支持与 a5 联动续接 | 支持模式的算法已恢复，采集输入仍有边界 | 支持记录中的 `aes`、`twofish`、`twofish-mod` 和 default/legacy 配置；需要原始 `a1`、匹配配置和 SIUA 明文。周期模式会同步已知缓存槽位并重加密，不会重新测量传感器或其他设备属性 |
| `a10` | 输出 `3,N`，`N` 来自 `signature_counter` | 当前原生初始化、构造与会话续接已证 | 原生启动 `srand(time(NULL)); N=rand()%254+1`，首段直接写 3；已观察 245→重启→228。已有会话从同条抓包续接；旧 1000 回退不是原生生成值 |
| `x0` | 当前原生布局写入整数 2 | 原生常量写入与跨布局差异已证 | 当前装配点直接写 2；另有 x0=4 请求具有不同 a* 字段类型/含义，不能沿用本表，其他布局枚举待证 |

`a5` 的 signing profile 与缓存 `a9` 的 profile 是两套选择，不能混用。旧文档把 x0 称为未定“标志”不足以指导处理；当前应以字段类型和布局共同判别，不能只看名称 mtgsig。

## 已经真正恢复的部分

- `a2` 的离线计算链：`a2` 的消息拼接、HMAC、表变换和 pass2 都有实现与合成/抓包对拍。
- `a5` 的 RC4 变体、zlib、密钥派生和严格解码；当前代码能对支持的 profile 加解密。
- `a9` 的外层 CRC/zlib/CBC、AES、Twofish 和修改 MDS 的 Twofish；支持严格校验和回编码。
- `a7/a8` 的本地候选格式，以及服务端响应回填状态机；回填值必须来自对应成功响应。
- `a4`、`a5.b2`、签名计数的已观测会话续接逻辑。
- b2/b17/b18 的当前原生计数分支，以及 b16 三组 SDK 上报次数、调用/HTTP200回调相对时间的字段映射；原生来源恢复不等于这些生命周期均已接入离线执行器。
- `periodic` 模式下的 60 秒采集缓存续接：从观察到的 `b1.58/b13` 起点推进，联动 `a5.b8/b9/b13/b1` 与 a9 的 `2[3]/2[9]`；保留已观察的 b9-b8 为0/1秒及独立采样毫秒差，所有观察时钟加相同整周期增量；已有非零 `2[15]` 同步推进，零保持零。原生 b8/b9 分别读取 siuaCollectTime/envCheckTime，未知差值仍拒绝。

周期刷新中的 `b1.55` 采用已有校验值的 CRC 差分，只支持其他输入不变、时间字符串等宽的形态。它没有恢复完整校验输入，也不支持任意修改设备字段后从零计算该值。默认 `captured` 模式仍保持原缓存；旧 `request` 模式只更新 `b8/b9`，不是完整联动刷新。

## 还没有完全恢复的部分

1. **完整设备采集器**：`a5` 和 `a9` 的密码已知，不代表可以从一台没有采样的设备生成同等 SIUA/采集画像。
2. **原生采集生命周期全貌**：已实现有观察基准的周期续接，但未恢复挂起/恢复、计时抖动、所有刷新触发和原始检测校验输入。b7 已定位为 SDK 单例首次构造的本地秒时间，不由周期模式逐请求刷新；b12 等其余项仍须分别追源。
3. **服务端身份**：`a7` 的 server XID、`a8` 的 server DFP 是服务端结果，不是客户端密码学字段。店铺链现对明确启用且材料匹配的账号主动上报、保存过期信息并到期刷新；完整原生画像、其他注册接口生命周期和全账号验收仍有边界。
4. **未来配置和未观察状态**：a10 初始化、a3 动态载荷和 Horn 回调/存储入口已定位；同次启动已证明先读存储、激活 25，再收到成功回调并写入同值，写入后未见重载。历史 20 会话缺少对应初始化日志，不能指定唯一根因；未来下发不同参数/盐仍需分别验证写入与激活。a6 已闭合开发团队/PIC 校验→S→0x01/0x02；全镜像非加密指令区识别到的 14 处直接地址构造均在 SDK 范围内，间接别名和未观察分支未被穷尽。
5. **跨版本配置自动识别**：已有实现只覆盖已验证的 profile/mode；未知 SDK 版本不能自动通解。

- `farm/fullsign.py`：构造器读取独立的 `sign_sequence` / `signature_counter`；`sign()` 只推进前者，`_fresh_a5()` 调用周期缓存并重新加密 a9。
