## 本次修正

1. `b17` 不再依赖 `b2-b17` 等于 0/1 的启发式：POST 推进一次，GET 保持；差值大于 1 的 POST 也继续推进。
2. `b18` 仅在显式 `sdk_user_id_state="nil"` 时推进。`non_nil` 保持，`unknown` 保留观察值，不由 HTTP userid、登录 token 或与 b2 相等来猜状态。
3. b2/b17/b18 出站使用原生 32 位值。本地保存单调累计量，防止回绕造成批次状态回退。POST/nil-user 计数独立持久化，并参与同会话续导入、旧状态迁移和新批次过期快照检查。
4. 老材料迁移以旧实现最后生成的计数为起点，保留原始 base_collect。迁移不能补造已经遗漏的历史原生事件。
5. `prepare_bundle()` 保留显式 `incognia_mode="generate"`，不再无条件强制 captured；数据库材料元数据同步记录实际模式。有完整安装材料时原有生成器会逐次生成 token、推进并持久化请求计数，生成失败仍保留已占用计数。
6. 材料不完整、没有签名设备状态的账号仍可导入为 `needs_material`，不会因缺少 `incognia_mode` 字段报错，也不把这种材料误标为可请求。

当前这批导入材料缺少各自的 Incognia 安装状态和配置，所以本次没有把它们直接改成 generate，也没有用别的安装状态代替。兼容模式仍明确记为 captured，不宣称已经完成全生命周期动态更新。现有 render b16 的最小出站适配保留；它不是实际调用 device-info，也不代表已经补齐其生命周期。
