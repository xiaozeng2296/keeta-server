编码链：字段 JSON → 现算 m320 → SDK envelope 压缩/对称加密/RSA 封装 → `{"encryptVersion":"3","src":"1","fingerPrintData":...}` → 使用该账号当前身份签名最终 POST URL 和 body → 服务端 `data.result` → 后续 mtgsig.a7。

新的 envelope 可以自行产生 16 字节随机 key；不能无 key 解开某个未知历史 RSA envelope，不妨碍按已恢复明文输入生成一个新 envelope。模式按当前 SDK flag `% 3` 选择 `twofish-mod / twofish / aes`。这条路径通过了本地完整解码往返，以及真实服务端响应验证。

## 原生有效期与 b16

`0x38aa80` 的响应回调读取 `interval`，在 `0x38ad38..0x38ad78` 执行 `interval * 60`，以 `NSDate now` 加秒数，取整秒再乘 1000，写入 `expireXIDTimeDate`。同回调读 `result` 并写 `DFPXID`。因此当前响应的 `interval=30` 是 **30 分钟**，不是 30 秒或 30 小时；到期基于本地接收时间，serverTimestamp 另行保存。

证据：镜像 SHA256 `194747e820db2102408082b0670daa45fc066fb08e0606a341dc63896058130c`；脱敏反解键名与运算证据在 `exports/a7-maintenance-20261003/native-a7-expiry.json`。

b16 第二组三元组属于 info/report：调用时次数加 1，调用时点更新为 `floor(startSeconds)-b7`，实际 HTTP200 时更新成功回调时点。HTTP200 但业务拒绝仍是 HTTP 回调，不应更新 a7；非 200 不更新成功回调时点。其余组、resume、设备画像和源快照保持。

动态事件单独存于 `device.fingerprint_report_state`，由 FullSigner 覆盖出站 b16。没有改 `base_collect`，不会破坏 CollectionCache 与原始快照的哈希绑定。render 的既有第三组 0→1 出站规则仍保留，不把它记为真实 `/v5/device-info` 调用。

## 续证：首次上报校时与 #71 单字段对照（18:49 UTC）

原生首次成功 info/report 回调在 `0x38b15c` 的 dispatch_once block 建立时钟：
`setXidStartTime:` 写入回调时的 `CACurrentMediaTime()*1000`，
`setXidServerTime:` 写入响应 `serverTimestamp.longLongValue`。
getter `0x35c340` 输出 `server_ms + CACurrentMediaTime()*1000 - start_ms`，
任一基准为零则输出零；当前 SIUA version 12 中对应 `2[15]` / m315。
这不是每次业务请求随机生成，也不是每次上报都重置：此写入受当前原生进程的 dispatch_once 约束。
`0x38af18` 相邻的另一计数已明确为 `xidReqCount`，不能与 m315 校时时钟混为一谈。

当前正式维护器仍只保存 serverTimestamp 元数据，未自动接入这条校时链。
