## 最小差异

在账号 #132 的早期首页材料中，**只改变 b16 第三组三元组的第一个值，即 `/v5/device-info` 调用计数，从 0 到 1，就能使 render 403 变成 HTTP200 / code0，指定菜品全部返回。** 请求完成后再改回 0，仍然变回 403。以零基下标表示该分量为 `b16[2][0]`；b16 在线上传输仍然是字符串，不是请求体新增一个数组字段。

## 是否必须额外激活

对**当前服务端状态下的 #132**，本轮没有补发任何激活或上报请求，只改出站的该计数就完成了稳定的双向翻转。因此该账号这次的直接原因已经缩小为请求携带的这个分量；“必须在这轮先补发一次激活接口才能成功”不符合实验结果。

尚不能据此证明每个从未完成 SDK 上报的新设备都只需写 1。#132 之前已经在手机上正常使用过，服务端可能已有设备记录；#100–#115 本轮只做原始材料核验，没有发送请求。服务端是否同时检查首次上报状态、该计数的其他取值或其他版本规则，本轮未覆盖。

生产签名器、导入器和所有账号的 b16 都未批量改写。诊断字段修改只用于单次出站请求，正常计数持久化与证据留存保持原流程。协议实现若接入 b16 生命周期，应按真实 device-info 调用/回调事件更新计数与两项时间，并与同设备/同 SDK 会话关联；不能将缺少观察等同于“已激活”。
