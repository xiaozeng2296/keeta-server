# 更新当前协议

本项目只保留运行用的离线协议和必要验证。原生 hook、镜像仿真和旧注册登录研究留在 [整理前版本](MIGRATION.md)；需要进一步逆向时在研究工程中执行，不把私有抓包和设备依赖放回部署目录。

1. 保存同一会话的成功请求、失败请求及准确 App/SDK 版本，脱敏后记录差异；不要仅凭 HTTP403 判断是哪个字段。
2. 从 `mtgsig/api.py` 的 `op_decrypt` 或 RPC `/decrypt` 解出 a5/a9，对齐原始 method、canonical URL、body、payload、a1/a3/salt 和计数。a2 比较完整 16 字节。
3. 按 [字段状态](MTGSIG_FIELDS_STATUS.md) 区分请求字段、会话字段、缓存和服务端身份。a7 只能来自真实成功上报，不能靠本地随机值“刷新”。
4. 修改对应核心函数；Worker 与 RPC 共用代码，不复制第二套签名实现。更新必要的固定向量、反例和状态转换测试。
5. 执行 [测试](TESTING.md)，先验证原有样例不回退，再按用户明确范围做少量真实业务验证。离线往返不等于服务端接受。
6. 更新当前字段文档和变更证据。已被推翻的结论留 Git 历史，不复制多个“最新版本”。

签名库不导入 farm、RPC、数据库或研究工具。文件位置由包自身定位；新增算法资源必须有测试证明需要，正常部署从 Git 获取。
