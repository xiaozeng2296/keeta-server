## 运行数据

沿用现有 MySQL 账号与任务元数据，业务响应继续以 `KLF1:` 哈希引用对应本机 `.private/responses/`。账号加密密钥、已用/预留额度、业务冷却、安装锁和 a7 维护记录不重置。旧未提交响应 journal 仍仅重放 SQL；其中已废弃的流量字段不再计费或写入。

旧 SQLite 与原始研究资料留在旧工程，不重新引入本项目。ZIP 只有工作簿，长字段嵌入同一工作簿。历史验收报告只表示当时的运行，不能代替此次重构后的检查。

## 验证方式

1. 隔离源码副本执行全部现用回归和真实本机 HTTP 烟测。
2. 独立 MySQL 测试库核验账户锁、额度、失败恢复、菜单扩展、跳过和导出；业务网络使用模拟响应。
3. 36 个现有账号在固定时钟/随机源下离线比较四种业务请求与 a7 上报构造，共 180 项；仅记录摘要，不发送业务请求、不保存身份变化。
4. 确认实际没有采集中或在途任务后切换服务；保留账号与数据状态并检查实际 PID、页面、RPC、导出及路径。

验证结果以本轮执行记录为准，不把历史 100 店压测冒充本轮重新压测。

整理后版本文件由 271 个减至 161 个，测试脚本由 60 个减至 28 个。独立 MySQL 测试库的 269 项全部通过；默认运行跳过其中 33 项显式数据库集成测试。两种 unittest discover 方式均可使用，测试 HTTP 分组命名为 `http_api`，避免遮住运行包 `rpc`。36 账号的 180 项离线对比全部一致，另通过 9 次合成 RPC HTTP、Web 和代理进程生命周期检查。测试库已移除。

实际切换后：Web、Worker、RPC、Clash 核心监督进程、GOST 桥接均使用新模块入口；面板首页、账号/批次状态和静态资源返回 200，RPC 合成操作通过，执行器持有唯一数据库锁。14 张业务状态表和 961 个私有文件切换前后摘要一致；历史 execution-33 的 3 店、77 条菜品交付验收通过。本轮没有追加真实业务采集请求。
